Role versus key

thara-web-1 has to read the laboratory reports bucket. On Day 2 it did so with an access key typed into a file. From Day 5 it does so with a role. Suppose somebody gets a copy of the server's disk, or a shell on it. Steal the credential on each path and see what the attacker is holding, and for how long.

Day 2: a long-lived key

An access key of admin-<student id>, typed in with aws configure

  1. The key id and its secret, in plain text in ~/.aws/credentials
  2. is read by
  3. the command line on thara-web-1
  4. which signs requests as
  5. your admin user, with every permission it has

Day 5: an instance role

thara-web-role, handed to the server by its instance profile

  1. No file. The server asks its own metadata service
  2. which hands it
  3. temporary credentials: a key, a secret and a token, with an expiry time
  4. which sign requests as
  5. thara-web-role, with the two permissions in thara-reports-read
Nothing has been stolen yet.Choose "Steal the credential" on each path.
Temporary credentials from an instance profile last for a few hours at most, at the time of writing; six is used here as the outer limit. A stolen key can also be stopped early by deleting it in IAM, and nothing stops it otherwise. Thara Hospitals is fictional.
