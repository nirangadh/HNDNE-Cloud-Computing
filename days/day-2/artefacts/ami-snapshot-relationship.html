Availability zone a
Instance thara-web-1t3.micro, running the pilot page
Root volume8 GiB gp3. Lives in this zone only
The region (not tied to a zone)
SnapshotA point-in-time copy of the volume's blocks, kept in storage AWS runs on S3. It holds the bytes and nothing else
AMI thara-portal-v1Holds no data of its own. It records:
  • root device: built from the snapshot above
  • volume size and type: 8 GiB gp3
  • architecture: 64-bit x86
  • boot mode and virtualisation type
  • who may launch it: this account
Availability zone b
New instanceYou choose at launch: type, subnet, security group, key pair, tags. None of these come from the AMI
New root volumeCreated from the snapshot, in this zone. A separate disk from the original
Why it matters. Delete the snapshot and the AMI cannot launch anything. Delete the original instance and the AMI still works. The image depends on the snapshot, not on the server it was made from.
Simplified: an image can hold more than one volume, and each gets its own snapshot. In the lab you remove the data volume so the image holds the root volume only.
